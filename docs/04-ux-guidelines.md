# 04. UX-гайдлайны

Статус: draft v1 · Значения токенов (цвета, шрифт) это **предложение**: финально утверждаем в F00 на реальных экранах и проверяем контраст инструментом.

## 1. Принципы

1. **Скорость ввода.** Добавление траты за несколько секунд на любом устройстве.
2. **Понятность с первого взгляда.** Главное число экрана крупнее всего остального.
3. **Нет тупиков.** На каждом экране есть loading, empty, error и offline состояния.
4. **Не только цвет.** Доход и расход различаются знаком и иконкой, статус бюджета иконкой и текстом.
5. **Единообразие.** Один паттерн на одну задачу (`components/common`). Новый паттерн появляется только если существующий не подходит.
6. **Доступность по умолчанию.** WCAG 2.1 AA.

## 2. Дизайн-токены

Все визуальные значения живут в CSS-переменных темы (shadcn). В компонентах **только токены**: никаких `#hex`, `rgb()`, `bg-[#...]`, inline-style. Конфигурация Tailwind v4 в CSS (`@theme`), сверять через Context7.

### 2.1 Цвета (семантические токены)

| Токен | Назначение |
|---|---|
| `background`, `foreground` | Фон страницы и основной текст |
| `card`, `popover` (+ `-foreground`) | Поверхности карточек и всплывающих окон |
| `primary` (+ `-foreground`) | Главные действия, акцент. **Предложение: индиго**, чтобы не пересекаться с цветом дохода (зелёный) и расхода (красный) |
| `secondary`, `muted`, `accent` | Вторичные поверхности и приглушённый текст |
| `destructive` | Удаление, критические ошибки |
| `border`, `input`, `ring` | Границы, поля ввода, фокус |
| `income` | Доход. Предложение: зелёный (emerald) |
| `expense` | Расход. Предложение: красно-розовый (rose) |
| `warning` | Бюджет ≥ 80% |
| `success` | Подтверждения |
| `chart-1 … chart-5` | Цвета графиков |
| `sidebar-*` | Токены сайдбара shadcn |

Для каждого токена заданы значения для светлой и тёмной темы.

### 2.2 Палитра категорий

Категория хранит ключ цвета (`color`), а не hex. Допустимые ключи (12): `slate`, `red`, `orange`, `amber`, `lime`, `emerald`, `teal`, `sky`, `indigo`, `violet`, `pink`, `stone`. Каждому ключу соответствует токен `--cat-<key>` для светлой и тёмной темы. Список ключей хранится в одной константе (`features/categories`) и используется пикером и `CategoryBadge`.

### 2.3 Типографика

- Шрифт: **Inter** (variable), подключается локально (например через `@fontsource-variable/inter`), fallback `system-ui, sans-serif`. Внешний CDN не используем.
- Шкала: стандартная Tailwind. Заголовок страницы `text-2xl font-semibold`, заголовок карточки `text-base font-medium`, основной текст `text-sm`, подписи `text-xs text-muted-foreground`, ключевое число (KPI) `text-3xl font-semibold`.
- **Суммы и числа всегда `tabular-nums`**, чтобы столбцы выравнивались.
- Минимальный размер текста 12 px, основной 14 px.

### 2.4 Форма и отступы

- Радиус: один токен `--radius` (предложение 0.625rem), остальные производные.
- Отступы: шкала Tailwind (кратно 4 px). Вертикальный ритм страницы: `gap-6`, внутри карточки `gap-4`.
- Тени: минимум, границы важнее теней.
- Иконки: только lucide, размеры 16 (внутри текста), 20 (кнопки), 24 (акценты и пустые состояния).

### 2.5 Контраст

- Текст и иконки: ≥ 4.5:1. Крупный текст и элементы интерфейса: ≥ 3:1. Проверяем в обеих темах.
- Цвета графиков различимы в тёмной теме. Данные графика дублируются подписями и скрытой таблицей.

### 2.6 Анимации

- Длительность 150–200 мс, плавное появление и скрытие.
- `prefers-reduced-motion` отключает неэссенциальные анимации.
- Декоративных анимаций нет.

## 3. Адаптив и layout

| Диапазон | Навигация | Форма добавления | Особенности |
|---|---|---|---|
| < 768 px (mobile) | Нижняя панель (Dashboard, Transactions, Budgets, More) + плавающая кнопка «Добавить» | `Drawer` (снизу) | Фильтры в `Sheet`, одна колонка |
| 768–1023 px (tablet) | Нижняя панель или сворачиваемый сайдбар | `Dialog` | Две колонки на дашборде |
| ≥ 1024 px (desktop) | Постоянный сайдбар (shadcn `Sidebar`) | `Dialog` | Фильтры в строке над списком |

- Минимальная ширина: 360 px. Горизонтального скролла страницы нет. Широкий контент скроллится внутри своего контейнера.
- Переключение `Dialog` / `Drawer` инкапсулировано в `ResponsiveDialog` (один компонент на весь проект).
- Цели нажатия ≥ 44×44 px на мобильных.
- Safe-area (iOS): нижняя панель и FAB учитывают `env(safe-area-inset-bottom)`.

## 4. Обязательные состояния экрана

Каждая страница и каждый блок данных реализуют все пять. Это критерий приёмки в каждой спеке.

| Состояние | Реализация |
|---|---|
| **Loading** | Скелетон по форме контента (`LoadingSkeleton`). Спиннер только внутри кнопки при отправке |
| **Empty** | `EmptyState`: иконка, короткое объяснение, главное действие (например «Добавить первую трату») |
| **Error** | `ErrorState`: что случилось человеческим языком, кнопка «Повторить» |
| **Offline** | `OfflineBanner` сверху. Данные из кеша остаются доступны, записи помечены как ожидающие синхронизации |
| **Success** | Toast (`sonner`) для действий без смены экрана. Автоматически скрывается |

Единая обработка состояний: `QueryBoundary`. Страницы не реализуют эти ветки вручную.

## 5. Экраны

| Экран | Содержимое | Особенности empty / error |
|---|---|---|
| **Login / Register / Reset** | Форма, кнопка Google, кнопка «Попробовать демо», переключатель языка | Ошибки под полем и общий баннер. Тексты ошибок Firebase переведены |
| **Dashboard** | Переключатель месяца. KPI: доход, расход, итог. Donut расходов по категориям (топ-5 и «Другое»). Столбцы доход и расход по месяцам (последние 6). Последние 5 операций | Empty: призыв добавить первую операцию. Графики ленивые (скелетон) |
| **Transactions** | Месяц, фильтры, список, сгруппированный по дням (итог дня в заголовке), кнопка добавить | Empty месяца и empty результата фильтров (с кнопкой «Сбросить фильтры») разные |
| **Accounts** | Карточки счетов, баланс, добавить, архивировать, пересчитать баланс | Empty не бывает в норме (есть «Основной»), при архивации всех предлагается создать счёт |
| **Budgets** | Список бюджетов месяца: категория, лимит, прогресс, остаток | Empty: «Задайте лимит на категорию». Расходные категории без бюджета предлагаются кнопкой |
| **Categories** | Две вкладки (расходы, доходы), иконка, цвет, архив | Показ архивных по переключателю |
| **Import / Export** | Экспорт (диапазон, фильтры, разделитель). Импорт: шаги Загрузка, Колонки, Проверка, Результат | Ошибки строк в превью, без потери корректных |
| **Settings** | Профиль, валюта, язык, тема, экспорт всех данных, удаление аккаунта (опасная зона) | Удаление с повторным вводом пароля и подтверждением |

Список транзакций это **список по дням** на всех размерах экрана, не таблица (на desktop добавляются колонки внутри строки). Решение фиксируем для единообразия.

## 6. Ключевые взаимодействия

### Добавление транзакции

- Открывается из кнопки (desktop) или FAB (mobile) и по клавише `N` на desktop (Could).
- Поля по порядку: тип (расход по умолчанию), сумма (автофокус, `inputMode="decimal"`), категория, счёт, дата (по умолчанию сегодня), заметка.
- Сумма принимает запятую и точку, показывает сумму в формате валюты по потере фокуса.
- Категория: список недавно использованных сверху. Счёт: последний использованный.
- После сохранения: форма закрывается, toast «Добавлено», список обновляется сам (оптимистично).
- Ошибки валидации под полем, фокус на первое невалидное поле.

### Удаление

- **Транзакция:** без подтверждающего диалога, с toast и кнопкой «Отменить» (несколько секунд). Подтверждение не нужно, потому что действие обратимо.
- **Категория, счёт:** архивация (обратима). Удаление данных, аккаунта, массовые операции: `ConfirmDialog`.

### Навигатор месяца

- Стрелки предыдущий/следующий, выбор месяца, кнопка «Сегодня». Месяц хранится в URL (`?month=2026-09`).
- Будущие месяцы доступны (для бюджетов и запланированного).

### Фильтры

- Тип, категория, счёт, текстовый поиск по заметке (с debounce). Состояние в URL. Применяются к загруженному месяцу на клиенте.
- Видны активные фильтры (чипы) и кнопка «Сбросить».

### Бюджеты

| Использовано | Состояние | Отображение |
|---|---|---|
| < 80% | Норма | Обычный прогресс |
| 80–100% | Внимание | `warning` + иконка и текст «Осталось X» |
| > 100% | Превышение | `destructive` + иконка и текст «Превышено на X» |

Текст и иконка дублируют цвет.

### Доход и расход

- Расход: знак `−`, иконка стрелки вниз, токен `expense`. Доход: знак `+`, иконка стрелки вверх, токен `income`. Реализовано один раз в `MoneyText`.

## 7. Графики

- Recharts через shadcn `chart`, цвета из токенов.
- У каждого графика `aria-label` с кратким описанием и скрытая (visually-hidden) таблица с теми же данными.
- Подписи осей и tooltip форматируются через `Intl` и локаль.
- Пустой график заменяется `EmptyState`, не пустой рамкой.

## 8. Тексты (microcopy)

- Тон: спокойный, дружелюбный, без восклицательных знаков и жаргона.
- Кнопки: глагол («Добавить», «Сохранить», «Удалить»). Заголовки диалогов называют действие.
- Ошибки: что произошло и что делать дальше («Не удалось сохранить. Проверьте соединение и попробуйте снова»). Без технических кодов в тексте.
- Пустые состояния: одно предложение пользы и одно действие.
- RU: обращение на «вы». EN: простой нейтральный стиль.
- Все тексты через i18n, повторяющиеся (Сохранить, Отмена, Повторить) используют общие ключи `common.*`.
- Сообщения валидации формулируются единообразно для всех форм (общие ключи `validation.*`).

## 9. Доступность (чеклист)

- Все действия доступны с клавиатуры, порядок фокуса логичен, фокус виден (`ring`).
- Диалоги и Drawer возвращают фокус на вызывающий элемент. `Esc` закрывает.
- У иконок-кнопок `aria-label` (через i18n). Декоративные иконки `aria-hidden`.
- Поля имеют `label`, ошибки связаны через `aria-describedby`, статус валидации объявляется.
- Динамические уведомления (toast) имеют `role="status"` (обеспечивает sonner, проверить).
- Контраст соответствует разделу 2.5. Информация не передаётся только цветом.
- Уважаем `prefers-reduced-motion` и `prefers-color-scheme`.
- Проверка: `@axe-core/playwright` в e2e на ключевых экранах и ручной проход с клавиатуры в F13.

## 10. Тёмная тема

- `light | dark | system`. Класс `dark` на `<html>`, применяется до монтирования React (нет мигания).
- Все токены имеют тёмный вариант. Графики и цвета категорий проверены в тёмной теме.
- Не используем чисто чёрный `#000` и чисто белый текст на чёрном (токены подбираем с мягкими значениями).

## 11. Проверка UX

Перед закрытием фичи: все пять состояний, mobile (360 px) и desktop, светлая и тёмная тема, EN и RU (длинные русские строки не ломают вёрстку), клавиатура, offline. Выполняется через скилл `verify`.
