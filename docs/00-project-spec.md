# 00. Спецификация проекта

Статус: draft v1 · Рабочее название: **FinTrack**

## 1. Цель

Веб-приложение для учёта личных финансов: доходы, расходы, категории, счета, бюджеты, аналитика, CSV-импорт и экспорт.

Проект делается **для портфолио фрилансера**. Он должен за 5 минут показать заказчику:

1. Работающую live-демку без регистрации.
2. Качество кода: структура, типы, тесты, CI.
3. Продуманные решения: ADR, README, кейс-стади.
4. Зрелый UX: состояния загрузки, пустые и ошибочные экраны, мобильная версия, тёмная тема, i18n.
5. Корректность и безопасность: деньги, даты, Security Rules с тестами.

## 2. Аудитория

| Кто | Что ему нужно |
|---|---|
| **Заказчик или техлид** (смотрит портфолио) | Быстро открыть демо, оценить UX, заглянуть в репозиторий, увидеть тесты, CI и решения |
| **Пользователь приложения** | Быстро записать трату, увидеть, куда уходят деньги, не выйти за бюджет, вывести данные в CSV |

Аудитория международная и СНГ: интерфейс EN (по умолчанию) и RU, README на EN и RU.

## 3. Продуктовые принципы

1. **Быстрый ввод.** Добавить трату должно быть возможно за несколько секунд (кнопка быстрого добавления, разумные значения по умолчанию).
2. **Данные пользователя принадлежат ему.** Экспорт всех данных и полное удаление аккаунта входят в MVP.
3. **Точность важнее красоты.** Деньги и даты считаются без погрешностей.
4. **Никаких тупиков в UI.** У каждого экрана есть состояния loading, empty, error, offline.
5. **Один «вау»-эффект лучше пяти средних.** Наш выбор: бюджеты с прогресс-барами и CSV-импорт с превью и валидацией.

## 4. Скоуп (MoSCoW)

| Приоритет | Что входит |
|---|---|
| **Must (MVP)** | Auth (email и Google), категории, транзакции (CRUD, фильтры, навигация по месяцам), дашборд, CSV-экспорт, demo-режим, адаптив, тёмная тема, i18n (EN и RU), Security Rules и тесты, CI, деплой |
| **Should** | Счета и балансы (UI), бюджеты, CSV-импорт с превью, удаление аккаунта и данных, экспорт всех данных |
| **Could** | PWA и offline-install, Cmd+K палитра, теги, повторяющиеся транзакции (материализация при открытии), переводы между счетами, AI-категоризация (stretch) |
| **Won't (v1)** | Мультивалютные курсы, банковские интеграции, общие кошельки, полнотекстовый поиск по всей истории, вложения (чеки), серверный код (Cloud Functions), UI на украинском (архитектура i18n допускает добавление) |

## 6. Нефункциональные требования

| Область | Требование | Как проверяем |
|---|---|---|
| **Корректность денег** | Только целые minor units, форматирование через `Intl` | Unit-тесты `money.ts` |
| **Корректность дат** | Дата транзакции строка `YYYY-MM-DD`, без часовых поясов | Unit-тесты `dates.ts` |
| **Безопасность данных** | Пользователь читает и пишет только `users/{свой uid}/**`. Невалидные данные отклоняются правилами | Тесты Security Rules на эмуляторе в CI |
| **Безопасность клиента** | Нет секретов в git, App Check, CSV-injection экранируется, API key ограничен по referrer | Ревью и чеклист F13 |
| **Производительность** | Lighthouse ≥ 90 (Performance, Accessibility, Best Practices). Тяжёлые страницы грузятся лениво. Целевой размер входного чанка уточняем в F13 | Lighthouse в F13 |
| **Доступность** | WCAG 2.1 AA: клавиатура, фокус, контраст, aria-подписи, `prefers-reduced-motion` | axe в e2e, ручная проверка |
| **Адаптивность** | От 360 px. Мобильная навигация внизу, форма добавления как Drawer | e2e на mobile viewport |
| **i18n** | EN и RU, плюрали, даты и числа через `Intl`. Нет жёстких строк в JSX | ESLint-правило и ревью |
| **Offline** | Чтение из локального кеша, запись в очередь с синхронизацией, индикатор сети | e2e (emulate offline) |
| **Браузеры** | Последние 2 версии Chrome, Firefox, Safari, Edge. iOS Safari 16+ | Ручная проверка |
| **Стоимость** | Остаёмся на бесплатном плане Spark. Расход чтений и записей контролируем (см. `02-data-model.md`) | Ревью запросов |
| **Поддерживаемость** | DRY, границы слоёв проверяет ESLint, `strict` TS, `noUncheckedIndexedAccess` | CI |

## 7. Ограничения и допущения

- Нет собственного сервера. Вся защита на Security Rules, вся логика в клиенте.
- Одна базовая валюта на пользователя. Поддерживаются валюты с двумя десятичными знаками (список в `lib/currencies.ts` и в rules).
- Поиск по заметкам только внутри загруженного месяца.
- Баланс счёта хранится как число и обновляется атомарно вместе с транзакцией.
- Разработка идёт против эмуляторов Firebase. Боевые проекты только для preview и prod.

## 8. Глоссарий

| Термин | Значение |
|---|---|
| **Minor units** | Наименьшая денежная единица (копейки, центы). `$10.50` хранится как `1050` |
| **Base currency** | Валюта пользователя, одна на весь аккаунт |
| **Account (счёт)** | Кошелёк: наличные, карта, банк. Имеет баланс |
| **Category** | Категория расхода или дохода. Не удаляется, а архивируется |
| **Transaction** | Операция: расход или доход. `amount` всегда положительный, смысл задаёт `type` |
| **Budget** | Лимит расходов по категории на конкретный месяц |
| **Month window** | Выбранный месяц. Единица загрузки данных вместо пагинации |
| **YearMonth** | Строка `YYYY-MM` |
| **systemKey** | Ключ дефолтной сущности (категории, счёта). Название берётся из переводов, пока пользователь не переименовал |
| **Repository** | Единственное место, где код обращается к Firestore |
| **Demo user** | Анонимный пользователь Firebase с подготовленными данными |
| **Spec (спека)** | Документ с требованиями и контрактами для реализации одной фичи |

## 10. Критерии успеха проекта

- Демо открывается по ссылке и показывает наполненный дашборд без регистрации.
- CI зелёный: typecheck, lint, unit, rules-тесты, build, e2e. Preview-деплой на каждый PR.
- README содержит скриншоты или GIF, схему архитектуры, раздел «Решения и компромиссы».
- Есть `docs/adr` с осмысленными решениями, история коммитов читается.
- Lighthouse ≥ 90, a11y без критичных нарушений.
- Кейс-стади на двух языках готов для профиля на фриланс-платформе.

## 11. Риски

| Риск | Влияние | Меры |
|---|---|---|
| Квота Spark исчерпана демо-трафиком (записи при сидировании) | Приложение перестаёт писать | Компактный сид (~100 записей), контроль запросов. План Б: in-memory демо (репозитории за чёткой границей это позволяют). Детали: `02-data-model.md` |
| Накопление анонимных аккаунтов | Мусор в базе | Проверить автоочистку и TTL в документации при F12. Документировать |
| Агент (быстрая модель) выдумывает API или нарушает границы | Баги, регресс | Спеки с контрактами, ESLint-границы, `verify`, Context7, маленькие задачи |
| Ошибка в Security Rules | Утечка данных | Rules-тесты в CI, изменение rules только с явным ревью |
| Дрейф баланса счёта | Неверные суммы | Атомарные batch-записи, функция пересчёта, тесты |
| Раздувание скоупа | Проект не закончен | MoSCoW, вертикальный порядок фич, правило «Won't» |
