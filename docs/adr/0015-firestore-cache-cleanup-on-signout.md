# ADR-0015: Очистка локального кеша Firestore и полная перезагрузка при выходе пользователя

* **Статус**: Accepted
* **Дата**: 2026-10-02
* **Автор**: Senior Tech Lead / FinTrack Team

## Контекст и проблема
FinTrack является одностраничным приложением (SPA), использующим Firebase Auth и Cloud Firestore с локальным IndexedDB-персистенсом (offline cache).
При выходе пользователя (`signOut`) возникает угроза утечки приватных финансовых данных:
1. Если на одном устройстве приложением пользуются несколько человек (например, домашний или общий компьютер), следующий пользователь может увидеть закешированные данные предыдущего пользователя из IndexedDB или памяти приложения до первой синхронизации.
2. Подписки `onSnapshot` и внутренний in-memory кеш Firestore SDK могут удерживать документы в памяти процесса.
3. Обычный переход внутри SPA через роутер (`navigate('/login')`) оставляет память JS-кучи нетронутой, включая состояния React, контексты и синглтон-клиенты Firebase.

При этом вызов `clearIndexedDbPersistence(db)` в Firestore SDK требует предварительного завершения работы клиента (`terminate(db)`), но может выбросить ошибку `failed-precondition`, если открыты другие вкладки приложения с активным Firestore, либо если есть незавершённые транзакции/записи.

## Рассмотренные варианты
1. **Только `signOut()` без очистки кеша и навигация через роутер (`navigate('/login')`)**
   - *Минусы*: Данные предыдущего пользователя сохраняются в IndexedDB и оперативной памяти; высокий риск утечки приватных данных на общих устройствах.
2. **Очистка данных «best effort» (`terminate` + `clearIndexedDbPersistence`) и жесткий редирект (`window.location.assign`) (Выбранный)**
   - *Плюсы*: Гарантирует сброс всей оперативной памяти SPA и отключение всех подписок. Очищает локальный IndexedDB-кеш. Если очистка IndexedDB падает из-за других вкладок, выход всё равно завершается успешно, а ошибка логируется.
3. **Блокирующий выход с ожиданием закрытия всех вкладок**
   - *Минусы*: Плохой UX; пользователь не может выйти, если открыта фоновая вкладка.

## Решение
При выходе пользователя (`useSignOut`):
1. Вызывается `signOutUser()` через Firebase Auth SDK (`signOut(auth)`).
2. Вызывается best-effort функция `clearLocalFirestoreData()` (`src/lib/firestore/session.ts`), которая пытается вызвать `terminate(db)` и затем `clearIndexedDbPersistence(db)`. Любые исключения перехватываются и логируются через `logger.warn`, не прерывая процедуру выхода.
3. Выполняется полная перезагрузка страницы на маршрут входа: `window.location.assign(ROUTES.login)`.

## Последствия
### Положительные:
* Изоляция пользовательских данных: следующий пользователь на том же устройстве не увидит следов данных предыдущей сессии.
* Полный сброс React-дерева, глобальных синглтонов и фоновых обработчиков в браузере.
* Надёжность: ошибка очистки IndexedDB (например, из-за мульти-вкладочности) не блокирует выход пользователя из аккаунта.

### Отрицательные / Компромиссы:
* Полная перезагрузка страницы (`window.location.assign`) занимает чуть больше времени, чем клиентский `navigate()`, и влечёт повторную загрузку скриптов из кеша браузера. Для сценария выхода это осознанный и рекомендуемый компромисс безопасности.
